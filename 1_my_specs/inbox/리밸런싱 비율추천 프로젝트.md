# [AI 기반 개인 맞춤형 주식 포트폴리오 리밸런싱 추천 서비스]

- **기간** : 25. 01 ~ 26.03
- **역할** : Backend Developer & Database Architect
- **상황/문제** :
  - **투자자 페인 포인트** : 개인 투자자들이 감정에 휘둘리는 의사결정과 복잡한 자산 배분 비율 산정에 어려움을 겪음.
  - **기술적 도전 과제** : 실시간 금융 데이터(Codef API)와 고도화된 AI 모델(TGNN, DDPG)을 안정적으로 결합할 백엔드 인프라 필요.
  - **DB 이슈** : 초기 설계 시 데이터 중복 및 복합 조회 성능 저하로 인한 삽입/삭제/갱신 이상 현상 발생.
  - **보안 이슈** : 단순 JWT 사용 시 토큰 탈취에 따른 보안 취약점 및 사용자 편의성 간의 트레이드오프 발생.
- **내가 한 일** :
  - **데이터베이스 아키텍처 설계** : MySQL 기반의 3차 정규화(3NF)를 수행하여 데이터 무결성 확보 및 JPA를 활용한 엔티티 매핑.
  - **사용자 인증 및 보안 시스템** : Spring Security와 JWT(Access/Refresh Token) 기반 인증 체계 구축, Redis를 활용한 토큰 관리 및 이메일 인증 TTL 처리.
  - **금융 데이터 파이프라인 구축** : Codef API를 연동하여 국내 주요 증권사 계좌 정보를 실시간 동기화하고 다중 계좌 통합 View API 구현.
  - **AI 모델 서빙 연동** : Flask 기반 AI 서버와 RESTful API 통신을 구현하여 TGNN Score 및 DDPG 추천 비율을 비동기적으로 처리 및 히스토리 관리.
  - **인프라 최적화** : Redis 캐싱을 통한 API 응답 성능 개선 및 확장 가능한 계층형 아키텍처(Controller-Service-Repository) 설계.
- **결과** :
  - **수상** : 2025년 1학기 기업연계 프로젝트 우수팀 경진대회 **동상(4등) 수상** .
  - **성과** : 하이브리드 AI 모델 **특허 출원** 및 관련 논문 작성 중.
    - **모델 성능** : TGNN 모델 예측 정확도 MSE 2.02 달성 (기존 CNN-LSTM 대비 **60% 개선** ).
    - **수익률** : 백테스팅 결과 하이브리드 모델 기준 연간(Annual) 리밸런싱 시 **CAGR 9.3%** , MDD -25.2%의 안정적 성과 확인.
    - **시스템 안정성** : 정규화를 통한 데이터 이상 현상 제거 및 Redis 도입으로 보안성과 UX 동시 확보.
- **배운 점** :
  - **DB 설계의 정교함** : 단순 CRUD를 넘어 정규화와 인덱싱 전략이 시스템의 확장성과 무결성에 미치는 결정적인 영향을 체득함.
  - **보안과 UX의 균형** : 보안 강화가 사용자 경험을 해치지 않도록 Refresh Token과 Redis를 조합하는 실무적 솔루션 역량을 갖춤.
  - **융합형 개발 역량** : AI 모델(TGNN, DDPG)의 특성을 이해하고 이를 백엔드 시스템과 효율적으로 결합하는 데이터 파이프라인 설계 경험을 쌓음.
  - **협업의 가치** : API 명세 문서화(Notion)와 정기 스크럼을 통해 프론트엔드 및 AI 파트와 기술적 간극을 줄이는 소통의 중요성을 깨달음.

# [TradingGate Backend: 원장 중심 이벤트 드리븐 트레이딩 시스템]

- **기간** : 25.11 ~ 26.03
- **역할** : Backend Developer (Trading API & Risk Management 전담)
- **상황/문제** :
  - **정합성 및 신뢰성** : 거래 이벤트의 안정적 처리와 '돈의 이동'을 어떻게 검증 가능한 구조로 유지할 것인가에 대한 도전.
  - **동시성 및 확장성** : 고빈도 체결 이벤트 발생 시 포지션 계산의 동시성 제어 및 DB I/O 부하 최적화 필요.
  - **시스템 분리** : 단일 애플리케이션 내에서 매칭, API, 리스크 관리 로직이 섞여 발생하는 역할 중첩 및 장애 전파 위험.
- **내가 한 일** :
  - **원장 중심 아키텍처 설계** : `ledger_entry`를 **SSOT(Single Source of Truth)**로 설정하고, `account_balance`를 조회용 **Projection**으로 분리하여 데이터 정합성 보장 전략 수립.
  - **Trading API Layer 구현** :
    - Kafka 기반 비동기 주문 접수 패턴 적용 및 심볼별 파티셔닝 라우팅 설계.
    - Redis와 DB Unique 제약을 결합한 **이중 멱등성(Idempotency)** 처리로 중복 요청 원천 차단.

  - **Risk Management 모듈 구축** :
    - `trades.executed` 이벤트를 소비하여 실시간 포지션 및 미실현 손익(uPnL) 계산 로직 구현.
    - **Write-behind 패턴** 적용: 메모리 연산 후 100건 단위 Bulk Update를 통해 DB 부하 최소화.
    - **리스크 제어 시스템** : 위험 감지 시 **Transactional Outbox 패턴**을 활용해 유저 차단 및 주문 취소 이벤트를 원자적으로 발행.

- **결과** :
  - **데이터 정합성** : 원장 대사 결과 불일치 **0건(recon_diff = 0)** 검증 완료.
  - **대용량 처리 성능** : 75,000건 이상의 Ledger 엔트리 및 10,000건 이상의 정산 결과 배치 처리 안정성 확인.
  - **리스크 대응 속도** : 위험 감지 시 제어 이벤트 발행 및 처리 시간을 **100ms 이내**로 보장.
  - **검증 체계 확보** : K6 부하 테스트(Smoke, Soak, Burst)를 통한 파이프라인 전 구간 성능 및 안정성 지표 확보.
- **배운 점** :
  - **이벤트 드리븐 설계의 깊이** : 단순히 메시지 큐를 쓰는 것이 아니라, **이벤트 계약(Schema)**의 사전 정의와 **소비자 멱등성** 설계가 결합도와 신뢰성에 미치는 영향을 깊이 체득함.
  - **아키텍처적 트레이드오프** : Write-behind를 통한 성능 향상과 메모리 유실 리스크 사이의 균형점을 찾고, 이를 보완하기 위한 스냅샷 및 리플레이 구조의 필요성을 이해함.
  - **검증 가능한 시스템** : "기능이 도는 것"과 "데이터가 맞음을 증명하는 것"의 차이를 깨닫고, 대사(Reconciliation) 로직을 아키텍처의 핵심으로 두는 습관을 갖게 됨.

### 🏛 핵심 설계 및 트러블슈팅

위 다이어그램은 주문 접수(`api`)부터 매칭(`worker`), 리스크 평가(`risk`), 원장 기록(`projection/clearing`)으로 이어지는 전체 흐름을 보여줍니다.

#### 🔴 주요 트러블슈팅: 포지션 동시성 해결

- **문제** : 다중 Risk 인스턴스 환경에서 동일 유저의 체결 이벤트가 동시 처리될 때 포지션 중복 계산 발생.
- **해결** : `userId` 기반 Kafka 파티셔닝으로 논리적 순서를 보장하고, `lock:position:{userId}` 키를 이용한 **Redis 분산 락**을 추가하여 물리적 배타성을 이중으로 확보함.

#### 🔴 주요 트러블슈팅: Outbox 페이지네이션 누락

- **문제** : 대량 배치 처리 중 오프셋 기반 조회로 인해 처리 완료된 레코드가 밀리면서 이벤트 발행 누락 발생.
- **해결** : **커서 기반(id > last_id) 페이지네이션**으로 변경하여 레코드 상태 변경과 무관하게 순차적 조회를 보장함으로써 누락 건수 0건 달성.

  - **문제 해결의 유연성** : API 제한이나 하드웨어 성능 차이 등 실무적인 제약 사항을 캐싱과 하이브리드 로직으로 극복하며 기술적 유연성을 기름.

#### 🔴 주요 트러블슈팅: API 호출 최적화

- **문제** : 빈번한 위치 갱신으로 인한 Weather API 일일 호출 한도 초과 및 서비스 중단.

- **상황/문제** :
  - **단기 역량 강화** : 4개월이라는 단기간 내에 임베디드, 빅데이터, 웹, AI 등 광범위한 풀스택 기술 역량을 실무 수준으로 끌어올려야 하는 고난도 과정.

  - **기업 연계 멘토링 프로젝트 수행** : 현업 개발자 멘토링을 통해 실무 요구사항을 분석하고, 이를 기반으로 한 맞춤형 솔루션 기획 및 제작.
  - **체계적 협업 프로세스 주도** : GitHub을 활용한 코드 리뷰 및 업무 분산 시스템을 구축하여 팀 프로젝트의 효율성 극대화.

# [전자정부 표준프레임워크(eGovFrame) 전문가 교육 이수]

- **기간** : 2024.10 ~ 2024.10
- **기관** : 한국지능정보사회진흥원(NIA)
- **목표** : 공공 정보화 사업의 표준 아키텍처 이해 및 SW 재사용성·품질 향상을 위한 표준 기술 습득
- **상황/문제** :
  - **표준화의 필요성** : 대규모 공공/민간 프로젝트에서 개발자마다 상이한 코딩 스타일과 구조를 통일하고, 시스템 간 상호 운용성을 확보해야 하는 과제 직면.
  - **실무 적용 역량** : 단순 Spring 사용을 넘어 전자정부 표준에서 정의한 실행·개발·운영·관리 환경의 유기적 연결 구조를 이해해야 함.
- **내가 한 일** :
  - **표준 아키텍처 학습** : Spring 프레임워크 기반의 7대 레이어(공통기반, 화면처리, 데이터처리, 연계통합, 업무처리, 배치처리, 모바일 처리)에 대한 심화 학습.
  - **실행 환경 실습** : 공통 컴포넌트 활용 및 전자정부 전용 IDE를 이용한 프로젝트 생성, 빌드, 배포 전 과정 수행.
  - **모바일 및 연계 기술 습득** : 모바일 디바이스 API 및 시스템 간 데이터 연계(Interface) 표준 기술 실습.
  - **전문가 인증 시험** : 교육 과정 종료 후 실시된 종합 평가 및 실무 역량 테스트 응시.
- **결과** :
  - **교육 수료 및 자격 획득** : 전자정부 표준프레임워크 교육 **수료증 취득** 및 최종 시험 합격.
  - **표준화 역량 확보** : 공공 사업 가이드라인에 부합하는 개발 생산성 증대 및 SW 품질 관리 기법 내재화.
  - **실무 투입 준비** : 대규모 SI 프로젝트의 표준 아키텍처를 즉시 이해하고 개발에 참여할 수 있는 이론적/실천적 토대 마련.
- **배운 점** :
  - **표준의 가치 체득** : 잘 정의된 프레임워크가 개발 생산성을 높일 뿐만 아니라, 장기적인 유지보수와 시스템 확장성에 얼마나 결정적인 역할을 하는지 깨달음.
  - **재사용성 극대화** : 공통 컴포넌트의 체계적인 활용법을 배우며, '바퀴를 다시 발명하지 않는' 효율적인 개발 방식의 중요성을 학습함.
  - **공공 프로젝트 메커니즘 이해** : 대한민국 정보화 사업의 기술적 근간을 이해함으로써, 향후 공공기관 및 대형 엔터프라이즈 프로젝트 수행 시 필요한 전문 지식을 갖추게 됨.
