## 📖 프로젝트 소개

**AI 기반 개인 맞춤형 주식 포트폴리오 리밸런싱 추천 서비스**

본 프로젝트는 개인 투자자들이 포트폴리오 관리에서 겪는 감정적 의사결정과 최적 비율 산정의 어려움을 해결하기 위해 개발된 지능형 투자 지원 시스템입니다.

하이브리드 AI 모델을 활용하여 개인의 투자 성향과 실시간 시장 상황을 종합적으로 분석합니다. 

Temporal Graph Neural Network(TGNN)로 주식 간 동적 관계를 학습하고, Deep Deterministic Policy Gradient(DDPG)로 최적 자산 배분 비율을 제시합니다.

실시간 계좌 연동(Codef API)을 통해 사용자의 현재 포트폴리오를 자동으로 분석하고, AI가 계산한 최적 비율을 직관적으로 제시하여 전문가 수준의 투자 의사결정을 지원하는 크로스플랫폼 모바일 애플리케이션입니다.

## 🐛 트러블 슈팅

### 1. 데이터베이스 삽입, 삭제, 갱신 오류 발생

**문제 상황**

계좌 연동, 리벨런싱 기록, 포트폴리오 구성 등 다양한 속성을 가진 사용자 데이터에서 특정 조건에 따른 복합 조회가 빈번하게 발생했습니다. 초기 단일 테이블 구조로는 데이터 중복이 발생하고, 특정 속성값(ConnectedID, 리벨런싱 날짜, 포트폴리오 타입 등)으로 필터링할 때 삽입, 삭제, 갱신 이상의 문제로 쿼리 성능이 저하되는 문제를 겪었습니다.

**해결 과정**

**개념적 설계**

- 사용자, 계좌, 포트폴리오, 리밸런싱 기록 등 주요 엔티티를 식별하고 ERD를 통해 엔티티 간 관계를 정의했습니다.

**논리적 설계 및 정규화**

- 제1정규화(1NF): 반복 그룹 제거 및 원자값 분리
- 제2정규화(2NF): 부분 함수 종속성 제거
- 제3정규화(3NF): 이행적 함수 종속성 제거를 통해 User, Account, Portfolio, Rebalancing 테이블로 분리했습니다

**물리적 설계**

정규화된 테이블 간 JOIN과 서브쿼리를 활용하여 연결을 진행했습니다.

**결과 및 배운점**

- **데이터 무결성**: 정규화를 통해 데이터 중복이 제거되고 참조 무결성이 확보되었습니다
- **확장성**: 새로운 포트폴리오 타입이나 리밸런싱 전략 추가 시 기존 구조를 유지하며 확장 가능한 설계가 되었습니다

데이터베이스 설계 단계에서 정규화의 중요성과 인덱스 전략, 그리고 ORM 사용 시 발생할 수 있는 N+1 문제와 해결 방법을 깊이 이해하게 되었습니다. 특히 실무에서는 정규화와 성능 사이의 균형을 맞추는 것이 중요하다는 것을 배웠습니다.

### 2. JWT 토큰 보안 및 관리 이슈

**문제 상황**

초기 JWT 구현에서 Access Token만 사용했을 때, 토큰 탈취 시 보안 위험이 높았습니다. 또한 토큰 만료 시간을 길게 설정하면 보안이 약화되고, 짧게 설정하면 사용자 경험이 저하되는 트레이드오프가 있었습니다.

**해결 과정**

- **Refresh Token 방식 도입**: Access Token(15분)과 Refresh Token(7일)을 분리하여 발행했습니다.
- Refresh Token은 Redis에 저장하여 서버 측에서 무효화 가능하도록 구현했습니다.
- Access Token 만료 시, Refresh Token을 통해 자동으로 재발급하는 로직을 프론트엔드와 협업하여 구현했습니다.
- Redis의 TTL 기능을 활용하여 Refresh Token의 자동 만료를 관리했습니다.

**결과 및 배운점**

토큰 탈취 시 피해 범위를 최소화하면서도 사용자 경험을 저해하지 않는 인증 시스템을 구축할 수 있었습니다. **보안과 UX의 균형**을 고려한 설계의 중요성과, Redis와 같은 인메모리 DB의 실무 활용 방법을 체듵했습니다.

## 💡 회고 및 배운 점

### 🔧 백엔드 아키텍처 설계의 깊이 체득

Java 기반 Spring Boot 프레임워크를 활용하면서 단순한 CRUD 구현을 넘어, **확장 가능하고 유지보수성 높은 시스템 설계**의 중요성을 깨달았습니다. 특히 MSA 기반 설계, 계층형 아키텍처(Controller-Service-Repository), 그리고 의존성 주입(DI)의 실무적 가치를 경험하며 백엔드 개발자로서 한 단계 성장할 수 있었습니다.

### 🤝 크로스 도메인 협업의 가치 발견

프론트엔드, 서버 및 데이터베이스 구축, AI구축 세가지 파트로 나누어서 개발자간의 긴밀한 협업을 통해 **도메인 간 원활한 소통**이 프로젝트 성공의 핵심임을 배웠습니다. API 명세서를 Noton으로 문서화하고, 주 2회 정기 스크럼을 통해 진행 상황을 공유하면서, 기술적 소통 능력과 협업 방법론의 중요성을 실감했습니다.

### 💼 실전 서비스 개발의 복잡성 이해

학습용 프로젝트와 실제 서비스 개발의 차이를 몸소 체험했습니다. 보안(Spring Security), 성능(Redis 캐싱), 확장성(Docker/AWS ECS)을 모두 고려한 시스템 설계와 배포 과정에서, 프로덕션 레벨 개발의 까다로움과 책임감을 배웠습니다. 특히 Codef API 연동 과정에서 실제 금융 데이터를 다루며, 민감 정보 처리의 중요성을 절감했습니다.

### 🧠 AI와 백엔드의 융합 경험

TGNN, DDPG 등 최신 AI 기술을 백엔드 시스템과 연동하면서, 단순한 웹 개발을 넘어 **AI와 백엔드의 융합적 사고**의 중요성을 깨달았습니다. Flask 기반 AI 서버와의 RESTful API 통신 구현, 그리고 AI 모델의 예측 결과를 데이터베이스에 효율적으로 저장/조회하는 파이프라인 설계 경험은 미래 개발자로서 소중한 자산이 되었습니다.

### 📊 데이터 중심 의사결정의 중요성

백테스팅 결과를 바탕으로 리밸런싱 주기(월/분기/반기/연)를 최적화하고, 성과 지표(Sharpe Ratio, MDD)를 추적하며, **데이터 기반 의사결정**의 가치를 배웠습니다. 개발자의 직관이 아닌 실제 데이터와 지표로 시스템을 검증하고 개선하는 프로세스의 중요성을 체득했습니다.
