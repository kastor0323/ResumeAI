# 설득과 팀워크 (선제적 소통)

## 핵심 메시지

> 갈등이 생긴 후 설득하는 것이 아니라, 갈등이 생기기 전에 구조를 만들어 마찰을 원천 차단하는 것이 진정한 팀워크다.

## 대표 에피소드

### 하이브리드 AI 주식 리밸런싱 앱 프로젝트 - 사전 API 명세 문서화로 개발 마찰 방지

- **상황**: 이전 개발 프로젝트에서 API endpoint나 명세를 명확히 정의하지 않은 채 개발을 시작했다가, 프론트엔드와 백엔드가 서로 "이건 이렇게 되는 거 아니었어?"를 반복하며 진행 속도가 심각하게 더뎌진 경험이 있었음. 개발 중 수시로 물어보고 조율하는 과정이 반복되면서 병목이 발생했고, 서로 이미 다른 방향으로 만들어놓은 코드를 수정하는 비용도 컸음.

- **행동**:
  1. **과거 경험의 구조적 원인 분석**: 마찰의 근본 원인이 "소통 부재"가 아니라 "사전 합의된 구조의 부재"임을 인식.
  2. **사전 문서화 도입**: 하이브리드 AI 주식 리밸런싱 앱 프로젝트 착수 시, 코드를 한 줄도 짜기 전에 팀원들과 함께 다음을 먼저 확정하고 문서화:
     - **API 명세 및 Endpoint 정의**: 각 API의 Request/Response 스펙, 에러 코드 규격을 사전에 명문화.
     - **DB 스키마 설계**: 테이블 구조, 관계, 필드 타입까지 설계 단계에서 합의.
  3. **문서를 "단일 진실 공급원(Single Source of Truth)"으로 활용**: 개발 중 의문점이 생기면 서로에게 물어보는 대신 문서를 먼저 확인하는 문화를 정착시킴.

- **결과**: 프론트엔드-백엔드 간 인터페이스 불일치로 인한 재작업이 거의 발생하지 않았고, 각자 독립적으로 개발을 진행하면서도 통합 시 충돌이 최소화됨. 개발 속도가 눈에 띄게 향상되었으며, 팀 내 불필요한 마찰 없이 원활하게 프로젝트를 완수.

## 러닝 포인트

- 갈등은 해결하는 것보다 예방하는 것이 훨씬 효율적이다.
- 개발 속도는 코딩 속도가 아니라 **팀의 정렬(Alignment) 속도**에 달려있다.
- 문서화는 팀원을 설득하는 도구이자, 불필요한 소통 비용을 줄이는 시스템이다.
