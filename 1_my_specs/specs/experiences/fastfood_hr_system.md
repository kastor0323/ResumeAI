# 📖 상황 (Situation)
중소규모 매장(패스트푸드 지점 등)의 직원 관리를 효율화하기 위해 **Java 기반 GUI 인사관리 데스크톱 애플리케이션**을 기획 및 1인 개발했습니다. 사원 정보의 체계적 관리(CRUD)와 직급별 접근 권한 차등화 시스템을 구축하고 다중 필터 검색 기능 제공을 목표로 했습니다.

# 🎯 과제 (Task)
1. **DB 스키마 정규화 설계**: 산발적인 데이터 삽입을 피하고, 직급/부서/권한이 유기적으로 연결된 데이터베이스 초기 구조 수립.
2. **다중 조건 검색 기능 구현**: 지점별, 직위별 등 여러 조건을 동시에 적용해 인력을 조회하는 동적 필터 구성.
3. **성능 및 보안성 향상을 위한 기틀 마련**: 첫 SQL 적용부터 발생하는 한계를 인식하고 추후 서비스 확장에 대비한 기술적 고민 시도.

# 🚀 행동 (Action)
*   **공통 속성 추상화 및 테이블 정규화 진행**: 초기에 각 직권별로 테이블을 분리하려다 데이터 중복을 인지했습니다. 이에, 직책 공통 필드(이름, 연락처 등)를 뽑아내 하나의 핵심 부모 테이블로 묶고, 직책 맞춤형 컬럼은 자식 테이블로 빼내어 **외래 키(Foreign Key) 참조 관계로 결합하는 방식의 정규화를 도입**해 무결성을 지켰습니다.
*   **보안과 확장성을 고려한 다중 조건 쿼리 리뷰**: 초기 다중 검색 조회 시, 입력된 조건 유무에 따라 Java 내부에서 단순 텍스트 IF문으로 쌩(Raw) SQL 문자열을 이어 붙이는 방식을 채택했습니다. 하지만 이 과정에서 파싱 오버헤드로 인한 성능 저하와 SQL 인젝션(보안 위협) 등의 치명적인 단점이 발생할 수 있음을 깨달았습니다. 이를 방어하기 위해 향후 PreparedStatement 또는 Mybatis/JPA 같은 프레임워크의 도입 필요성을 도출해 내며 아키텍처 개선 과제로 스스로 진단했습니다.
*   **Java Swing 기반 애플리케이션 추상화**: GUI 화면단과 뒷단의 DB 통신 로직을 최대한 묶어내며 사용자 친화적 시스템을 구축했습니다.

# 🏆 결과 (Result)
*   데이터 중복 없이 직책간 권한 부여와 정보 관리가 가능한 RDBMS 환경의 인사관리 인프라를 성공적으로 완수했습니다.
*   DB 테이블 정규화부터 다중 조건 검색 질의 최적화 가능성 발견까지, 초기 개발 과정 중 겪는 '보안 및 유지보수성 문제'를 스스로 인지하고 분석하여 **단순 구현을 넘어선 탄탄한 기본기(문제 인식 역량)를 확인**했습니다.
