# 📖 상황 (Situation)
시각장애인 및 저시력자의 일상 편의를 위해 개발된 접근성 중심의 모바일 애플리케이션 개발 프로젝트를 진행했습니다. 3인 팀(FE 1명, BE 2명)의 팀장 및 백엔드/서버 개발을 담당하며, 사용자 중심의 서비스를 구축하는 것이 목표였습니다.

# 🎯 과제 (Task)
1. **Weather API와 GPS 기능 연동**: 사용자 현재 위치 기반의 실시간 날씨 데이터 수집 및 제공을 위한 안정적인 인프라 구축.
2. **저시력자 맞춤형 접근성 구현**: TTS(Text-to-Speech) 기능을 통해 사용자가 불편 없이 날씨 정보를 음성으로 전달받을 수 있도록 최적화.
3. **자원 및 디바이스 제약 극복**: 외부 날씨 API의 일일 호출 횟수 제한과 실내외 위치 정보 수집의 정확도 문제를 최소화하는 전략 마련.

# 🚀 행동 (Action)
*   **효율적인 API 호출 아키텍처 구현**: API 일일 한도 초과 문제를 해결하기 위해, 불필요한 주기적 갱신을 과감히 없앴습니다. 오직 **검색 혹은 사용자 본인의 위치 추적 액션이 발생할 때만 API를 호출하도록(On-Demand) 호출 시점을 최적화**했습니다. 아울러 로컬 캐싱 시스템을 통해 불필요한 반복 요청을 최소화했습니다.
*   **하이브리드 위치 정보 수집 적용**: 날씨 정보 제공을 위해서는 정밀한 좌표보다 '지역' 단위의 데이터면 충분하다는 본질을 간파했습니다. 따라서 GPS 무선 신호가 약한 실내에서는 **네트워크 기반 위치 서비스(Wi-Fi, 기지국 등)를 백업으로 활용하는 하이브리드 위치 추적 시스템**을 구현하여, 실내외 어디서든 끊김없이 지역 기반 날씨 정보를 확인할 수 있게 조치했습니다.
*   **플랫폼별 TTS 맞춤 분리**: iOS와 Android 간 TTS 엔진 차이에서 오는 음성 품질 이슈를 플랫폼별 TTS 설정을 분리하고, 구동 속도 및 톤업 기능을 이원화해 추가로 관리함으로써 해결했습니다.

# 🏆 결과 (Result)
*   일방적인 백그라운드 호출을 차단하고 사용자 액션 기반의 API 호출 설계로, **일일 API 호출 횟수 제한을 완벽하게 우회하고 안정적인 서비스 운영에 성공(API 최적화 달성)**했습니다.
*   세밀한 좌표 대신 목적에 맞는 '지역 기반 하이브리드 추적'을 적용해 **실내 음영 지역에서도 사용자 위치 인식 누락 지표를 0%로 만들며 앱의 신뢰성을 극대화**했습니다.
*   접근성 중심 앱 기획부터 개발까지 완수하며 React Native 크로스 플랫폼 개발 역량을 증명했고, 프로젝트 팀장으로서 기획, 일정, 소통을 성공적으로 리드했습니다.
