# AI 기반 자기소개서 자동 평가 및 분석 시스템

## Situation (상황)

취업 준비생이 자소서를 작성할 때 "내 자소서가 합격 수준인지" 객관적으로 검증할 방법이 없다는 문제에서 출발했습니다. 단순한 문법 교정을 넘어, 실제 합격 자소서의 언어적 패턴과 지원 기업의 핵심가치에 얼마나 정합되는지를 정량적으로 측정할 수 있는 웹 서비스를 기획·개발했습니다.

---

## Task (과제)

1. **합격 자소서 데이터 수집**: 링커리어(Linkareer) 합격 자소서 플랫폼에서 직무별 합격 사례 데이터를 크롤링해 평가 기준 데이터셋 구축
2. **도메인 특화 평가 알고리즘**: 합격 자소서 키워드 매칭과 기업 비전 정합성을 결합한 2-Factor 정량 평가 모델 설계
3. **안정적인 멀티 서버 아키텍처**: Spring Boot(메인 서버)가 Python Flask(NLP 서버)를 내부에서 호출하는 구조로 서버 간 책임을 명확히 분리

---

## Action (행동)

### 1. 링커리어 합격 자소서 데이터 크롤링 (BeautifulSoup4)

평가 기준이 될 합격 자소서 데이터를 직접 수집하기 위해 BeautifulSoup4로 링커리어를 크롤링했습니다.

**어려움 1 — 정적 파싱의 한계**

- `requests` 방식으로는 링커리어의 자소서 본문이 정상적으로 파싱되지 않는 문제 발생
- JavaScript로 동적 렌더링되는 요소들이 HTML 응답에 포함되지 않아 원하는 데이터를 추출하지 못함
- BeautifulSoup4의 CSS 선택자와 HTML 구조를 분석하며 접근 방식을 조정해 수집 성공

**어려움 2 — 한국어 키워드 추출 품질**

- 형태소 분석 후 추출된 명사 중 **동음이의어** 문제 발생 (예: 취업 자소서에서 "성장"이 회사 성장인지 개인 성장인지 문맥에 따라 다름)
- 한국어 특성상 조사·어미가 붙어 나오는 형태 때문에 일반 영어 불용어 처리와 달리 **도메인 특화 불용어 목록**을 별도로 정의해야 했음
- Kiwi 형태소 분석기의 품사 태그(N계열 명사만 추출)를 적극 활용해 노이즈를 줄이고, 자소서 도메인에서 무의미한 고빈도 단어를 수작업으로 정제

**결과물**: 직무·직위별로 분류된 합격 자소서 키워드 분석 CSV (`linkareer_keyword_analysis.csv`) 구축

### 2. 기업 비전 데이터 직접 구축 (232개 기업)

국내 대기업 계열사 **232곳**의 비전·핵심가치를 수집해 `companies.json`으로 직접 구축했습니다.

각 기업 데이터는 4개의 성향 테마로 정규화했습니다.

| 테마      | 주요 키워드                   |

| 기술/혁신 | 기술, 혁신, 초격차, R&D, 품질 |
| 미래/선도 | 미래, 선도, 글로벌, 변화      |
| 인재/협력 | 인재, 협력, 상생, 소통, 성장  |
| 실행/도전 | 도전, 열정, 책임, 완수        |

### 3. 2-Factor NLP 평가 모델 (가중치 설계 근거 포함)

#### 가중치 설계 근거 — 70 : 30

| 지표             | 가중치  | 설계 근거                                                                                                                                                     |
| ---------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 합격 키워드 매칭 | **70%** | 실제 합격자들이 공통적으로 사용한 언어 패턴을 직접 비교하는 가장 직접적인 합격 가능성 지표. 직무별 요구 역량이 합격 자소서에 압축·반영되어 있어 신뢰도가 높음 |
| 기업 비전 정합성 | **30%** | 기업 문화 적합성은 중요하지만 표현 방식의 다양성과 주관성이 높고, 같은 기업 내에서도 직무별로 요구하는 인재상이 달라질 수 있어 보조 지표로 설정               |

> 핵심 원칙: "직무 적합성(무엇을 할 수 있는가)"이 "기업 문화 적합성(어떤 사람인가)"보다 채용 판단에서 우선 반영된다는 취업 시장 도메인 지식을 가중치에 반영

#### Factor 1 — 합격 키워드 매칭 (70%)

- 링커리어 크롤링 데이터 기반 합격 자소서 키워드와 Kiwi 형태소 분석기로 추출한 사용자 답변 키워드를 **Jaccard 유사도**로 비교
- **3단계 Fallback 매칭**: 데이터 희소 직무에서도 평가 중단 없이 동작하도록 설계
  1. 직무 + 직위 완전 일치
  2. 직무만 일치 (신입/인턴 통합)
  3. 질문 유형 분류(지원동기·성장과정·장단점 등 8개 카테고리)로 전체 데이터 매칭
- **점수 산출**: 매칭 키워드 수 기반 구간별 점수 (16개 이상 → 100점)

#### Factor 2 — 기업 비전 정합성 (30%)

- 기업 성향 테마 적합도, 서사 구조 완성도(경험 근거 / 기술 자부심 / 비전 지향), 비전 액션 동사("이끌다, 기여하다, 혁신하다" 등) 매칭을 정규식 패턴으로 분석
- 단순 키워드 카운팅이 아닌 **서사 구조 분석**으로 "왜 이 회사를 지원했는지"의 논리적 흐름까지 측정

### 4. Spring Boot ↔ Python Flask 서버 간 연동 아키텍처

```
React → Spring Boot → Flask (/evaluate) → Spring Boot → MySQL
```

**변경 이유**: 현재 구조에서는 평가 요청·저장 두 API를 프론트엔드가 직접 조율하므로, 네트워크 오류나 저장 실패 시 평가 결과가 유실될 위험이 있습니다. Spring Boot가 `RestTemplate`으로 Flask를 내부 호출해 평가→저장을 하나의 트랜잭션으로 처리하면 데이터 정합성과 에러 핸들링 안정성이 높아집니다.

---

### 5. Spring Boot 백엔드 및 JWT 인증

- **JWT 인증**: `JwtTokenProvider`로 토큰 발급·검증, `JwtAuthenticationFilter`를 Security 필터 체인에 등록해 매 요청마다 토큰 유효성 검사
- **CORS 통합 설정**: Spring Security 적용 후 CORS 에러 발생 → `SecurityConfig`에서 Security 필터 체인에 CORS 설정을 직접 통합해 해결
- **DB 설계**: 복수 질문-답변을 `|||` 구분자로 결합 저장, 평가 세부 결과는 JSON 직렬화(`evaluation_details` LONGTEXT)
- **등급 산출**: 평균 점수 기준 S(80+) / A(60~79) / B(40~59) / C(~39)

## 트러블슈팅

### 1. 링커리어 크롤링 — 동적 렌더링 데이터 파싱 실패

- **문제**: `requests + BeautifulSoup4`로 합격 자소서 본문 파싱 시 원하는 데이터가 추출되지 않음
- **원인**: 링커리어의 자소서 본문이 JavaScript 동적 렌더링으로 삽입되어 정적 HTML 응답에 포함되지 않음
- **해결**: HTML 응답 구조를 반복 분석하며 BeautifulSoup4 CSS 선택자 접근 방식을 조정해 수집

### 2. 한국어 키워드 품질 — 동음이의어 및 불용어 처리

- **문제**: 형태소 분석 후 추출된 키워드에 취업 자소서 문맥에 무의미한 고빈도 단어와 동음이의어가 다수 포함
- **해결**: Kiwi의 품사 태그(N계열 명사)로 1차 필터링 후, 자소서 도메인 특화 불용어 목록을 직접 정의해 수작업 정제

### 3. Spring Security CORS 에러

- **문제**: Spring Security 적용 후 프론트엔드(port 3000) 요청이 CORS 에러로 차단
- **원인**: Spring Security 필터가 일반 CORS 설정보다 먼저 요청을 가로채는 구조
- **해결**: `SecurityConfig`에서 `cors(cors -> cors.configurationSource(corsConfigurationSource()))` 방식으로 Security 필터 체인에 CORS 설정 직접 통합
