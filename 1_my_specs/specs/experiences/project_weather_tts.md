# 📱 [저시력자 맞춤형 TTS 음성 날씨 알림 서비스]

## 1. 개요 (Overview)
- **기간** : 2024. 03 ~ 2024. 06
- **역할** : 프로젝트 팀장 (기획, 일정 관리, API 및 메인 로직 개발)
- **기술 스택** : `React Native`, `Expo`, `JavaScript (ES6+)`, `Weather API`, `Git / GitHub`, `SourceTree`

## 2. 상황 / 문제 (Situation & Task)
- **사회적 니즈** : 시각장애인 및 저시력자가 기존 날씨 앱의 복잡한 UI를 이용하기 어려운 불편함 존재.
- **기술적 제약** : API 호출 횟수 제한으로 인한 서비스 안정성 위협 및 플랫폼별(iOS/Android) TTS 엔진 호환성 문제 발생.
- **환경적 제약** : 실내 등 GPS 수신이 불안정한 환경에서 정확한 위치 기반 날씨 정보를 제공해야 하는 과제.

## 3. 내가 한 일 (Action)
- **팀 프로젝트 리딩** : 3인 팀의 팀장으로서 WBS 수립, GitHub/SourceTree를 활용한 협업 워크플로우 구축 및 일정 관리 전담.
- **크로스 플랫폼 앱 개발** : React Native와 Expo를 활용하여 Android/iOS 통합 코드 베이스 구축 및 UI/UX 접근성 가이드라인 준수.
- **데이터 파이프라인 구현** : OpenWeather API를 연동하여 현재 위치 기반 실시간 날씨 데이터를 수집하고, 효율적인 데이터 파싱 로직 구현.
- **접근성 핵심 기능 개발** : Expo-Speech(TTS) 엔진을 활용하여 기온, 하늘 상태 등 날씨 정보를 음성으로 출력하는 시스템 구축.
- **위치 최적화** : GPS 신호 약화 시 네트워크 기반(WPS) 위치 정보를 활용하는 하이브리드 트래킹 로직 설계.

### 🔴 주요 트러블슈팅
1. **API 호출 최적화**
   - **문제** : 빈번한 위치 갱신으로 인한 Weather API 일일 호출 한도 초과 및 서비스 중단.
   - **해결** : 유효 시간(TTL) 기반 **로컬 캐싱 시스템**을 도입하여, 짧은 시간 내 재요청 시 서버 통신 없이 저장된 데이터를 반환하도록 개선.
2. **플랫폼별 TTS 최적화**
   - **문제** : iOS와 Android의 기본 TTS 엔진 특성 차이로 인한 음성 속도 및 명확성 불일치.
   - **해결** : OS별 조건부 설정을 통해 음성 속도(Rate), 피치(Pitch)를 개별 최적화하고 사용자 커스텀 설정 기능을 추가하여 사용성 강화.

## 4. 정량적/정성적 성과 (Result)
- **서비스 안정화** : 로컬 캐싱 도입을 통해 일일 쿼터 제한 문제 해결하고 응답 속도를 향상시킴.
- **사용자 경험 극대화** : 고대비(High Contrast) UI 설계와 플랫폼별 맞춤형 TTS 설정을 통해 저시력자 타겟 사용자 만족도 확보.
- **기술 확장** : Java/Python 중심에서 JavaScript/React Native로 기술 스택을 확장하며 프론트엔드와 모바일 환경에 대한 높은 이해도 증명.

## 5. 배운 점 (Lesson Learned)
- **사용자 중심 설계(User-Centered Design)** : 기능을 구현하는 것을 넘어 특정 사용자 계층의 페인 포인트(Pain Point)를 기술로 해결하는 과정에서 개발자의 사회적 책임을 배움.
- **효율적인 협업 시스템** : 팀장으로서 코드 리뷰와 버전 관리 전략이 프로젝트의 완성도와 개발 속도에 미치는 긍정적인 영향을 체득함.
- **문제 해결의 유연성** : API 제한이나 하드웨어 성능 차이 등 제약 사항을 캐싱과 하이브리드 로직으로 극복하며 기술적 유연성을 기름.
