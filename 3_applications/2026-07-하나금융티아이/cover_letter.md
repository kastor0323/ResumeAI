### 2. 직무 적합성 - 직무 관련 경험(STAR 기법)

[원장 불일치 0건으로 증명한 데이터 정합성]

주식 거래 이상탐지 시스템(TradingGate)을 2인의 백엔드 팀원과 개발하며 전체 5개 서비스 중 Trading API와 Risk Management 모듈을 전담했습니다. 거래 시스템은 대량의 주문과 체결 이벤트가 유실이나 중복 없이 처리되어야 하고, 잔고 데이터의 신뢰성이 상시 검증되어야 한다는 두 가지 과제가 있었습니다. 저는 원장 데이터(ledger_entry)를 단일 진실 공급원으로 두고, 멀티 인스턴스 환경에서도 동시성 문제 없이 대용량 배치를 처리할 수 있는 구조를 설계해야 했습니다.

주문 접수 시 DB를 직접 조회하지 않고 Kafka의 orders.in 토픽에 비동기로 발행해 API 응답 지연을 최소화했고, (userId, clientOrderId) 복합키 기반 Redis 락과 DB Unique 제약을 이중으로 적용해 중복 요청을 차단했습니다. 동일 유저의 체결 이벤트가 여러 리스크 인스턴스에서 동시에 처리되며 발생하는 경쟁 조건을 막기 위해 분산 락(타임아웃 5초, 최대 3회 재시도)을 설계했고, 실시간 손익은 Redis에 우선 반영한 뒤 100건 단위로 DB에 일괄 반영해 대량 I/O 병목도 해소했습니다. 대용량 배치 처리 중 Offset 기반 페이지네이션이 처리 완료 상태 변화로 다음 페이지 레코드를 누락시키는 문제를 발견한 뒤에는, ID 비교 기반의 Cursor 방식으로 전환해 원인을 근본적으로 해결했습니다.

그 결과 총 75,000건의 원장 엔트리와 10,016건의 정산 데이터를 누락 없이 처리했고, 대사 프로세스 검증 결과 원장과 잔고 데이터 간 불일치가 완벽히 0건임을 확인했습니다. Prometheus와 Grafana로 포지션 및 손익 지표를 시각화해 장애 발생 여부를 즉시 관제할 수 있는 환경도 함께 구축했습니다.
