# 포스타입 백엔드 엔지니어 신입/경력 채용 자기소개서

## 1. 조직 적합성 (지원동기 및 기여 방안)
**[크리에이터의 가능성을 실현하는 린(Lean)한 개발자]**
누구나 기술적 장벽 없이 창작의 가치를 실현하고 수익을 창출하도록 돕는 포스타입의 비전은, 오버 엔지니어링을 지양하고 본질적인 문제를 효율적으로 해결하여 실질적인 임팩트를 남기고자 하는 저의 '실용주의 개발 철학'과 깊이 맞닿아 있습니다. 화려한 기술을 좇기보다 창작자와 팬덤이 교류하는 생태계 본연의 가치 창출에 집중하는 방향성에 깊이 공감했습니다.
최근 포스타입은 10주년을 맞이하며 누적 가입자 700만 명과 거래액 1,500억 원을 돌파했습니다. 또한 '리퀘스트' 서비스와 '캐릭터톡' 등 AI 기술을 접목하며 크리에이터 이코노미 시장을 주도하고 있습니다. 단순한 콘텐츠 소비를 넘어 팬덤과 창작자가 능동적으로 교류하는 환경에서는, 폭발적인 트래픽을 안정적으로 지탱하는 백엔드 인프라와 시장의 변화에 민첩하게 대응할 수 있는 린(Lean)한 업무 방식이 필수적입니다.
저는 백엔드 엔지니어로서 비즈니스 요구사항을 빠르고 안정적으로 구현하는 데 최적화된 역량을 쌓아왔습니다. 복잡한 시스템을 고도화할 때도 화려한 기술 스택의 도입보다는 '왜 이 기술이 필요한가'와 '효율성(ROI)'을 치열하게 고민했습니다. 일례로 AI 주식 리밸런싱 앱 개발 당시, 무거운 동기식 처리로 인해 스레드 고갈 문제가 발생했습니다. 아키텍처를 전면 재설계하기보다 WebClient와 비동기 스레드 풀(Async)을 도입해 최소한의 변경으로 메인 API 스레드 블로킹 시간을 0ms로 단축했습니다. 또한, DB 3정규화를 통해 데이터 무결성을 확보하며 시스템의 안정성을 높였습니다. 
불필요한 복잡도를 줄이고 시스템의 유지보수성을 극대화하는 실용적인 접근법으로, 포스타입이 수백만 크리에이터와 팬덤을 잇는 압도적인 플랫폼으로 성장하는 데 기여하겠습니다.

## 2. 직무 적합성 (직무 경험 및 문제 해결)
**[75,000건의 트래픽을 누락 없이 처리한 분산 시스템 설계]**
수백만 명의 사용자가 이용하는 포스타입 플랫폼에서는 유료 결제 및 후원 데이터의 유실과 중복을 원천 차단하는 백엔드 안정성이 가장 중요합니다. 저는 주식 거래 이상 감지 시스템(TradingGate) 프로젝트에서 API 및 리스크 관리 모듈을 구축하며 분산 환경의 정합성 문제를 성공적으로 해결한 경험이 있습니다.
당시 5개의 멀티 인스턴스에서 동시에 쏟아지는 거래 이벤트를 병목 없이 처리하고, 대용량 배치 프로세스에서 발생하는 레코드 누락 현상을 방지하여 시스템 무결성을 확보하는 것이 핵심 과제였습니다. 이를 위해 데이터 정합성을 철저히 보장하는 아키텍처를 설계했습니다.
첫째, 시스템 부하를 줄이기 위해 CQRS 패턴을 적용하여 쓰기와 조회 DB를 분리했고, Kafka를 통해 비동기 이벤트를 발행해 병목을 차단했습니다. 둘째, 다중 인스턴스 환경의 동시성 이슈를 제어하기 위해 Redis 분산 락(timeout 5초)을 도입하여 Race Condition을 방지하고 멱등성을 이중으로 보장했습니다. 실시간 손익 계산은 Write-behind 패턴을 통해 Redis에 우선 캐싱한 뒤 100건 단위로 DB Bulk Update를 수행하여 I/O 부하를 대폭 줄였습니다. 
마지막으로 대용량 배치 처리 과정의 버그를 해결했습니다. 75,000건 이상의 데이터 처리 중 상태 변경에 의해 오프셋이 밀려 누락이 발생하는 원인을 파악하고, 기존 방식에서 Cursor-based(ID 비교) 기반의 페이지네이션으로 전환하여 안정성을 높였습니다. 
결과적으로 75,000건의 원장 처리와 10,016건의 정산 결과를 단 1건의 누락이나 중복 없이 완벽히 처리하며 대사 불일치율 0%를 달성했습니다. 포스타입에서도 데이터 정합성과 성능을 모두 충족하는 안정적인 서비스를 제공하겠습니다.

## 3. 의사소통 방식 및 협업 (팀워크 경험)
**[충돌을 원천 차단하는 문서화 기반의 선제적 소통]**
포스타입과 같이 매트릭스 조직으로 운영되며 프로젝트 단위로 유연하게 일하는 환경에서는 직군 간의 원활한 소통과 정렬(Alignment)이 프로젝트의 성공을 좌우합니다. 저는 갈등이 발생한 후 수습하는 것이 아니라, 구조적인 문서화 체계를 통해 마찰을 선제적으로 예방하는 소통 방식으로 효율성을 극대화한 경험이 있습니다.
하이브리드 AI 주식 리밸런싱 앱 프로젝트 초기, 프론트엔드와 백엔드 개발자 간 API 명세 및 데이터 규격이 명확히 합의되지 않아 병목 현상이 발생할 우려가 있었습니다. 과거 다른 프로젝트에서 사전 조율 부재로 잦은 코드 수정과 소통 비용의 낭비를 겪었기에, 이를 방지할 근본적인 시스템이 필요하다고 판단했습니다.
이에 '문서 중심의 단일 진실 공급원(SSOT)' 문화를 주도적으로 정착시켰습니다. 본격적인 코딩 전 회의를 열어 모든 API의 Request/Response 스펙, 에러 코드 규격, DB 스키마 등 핵심 구조를 철저히 문서화했습니다. 의문점이 생기면 개인적으로 묻기보다 문서를 기준으로 논의하도록 유도했고, Pull Request 기반의 Peer Review 제도를 도입해 병합 전 논리적 오류와 인터페이스 불일치를 사전에 검증하도록 제도화했습니다.
이러한 선제적인 소통 시스템 덕분에 프론트엔드 연동 과정에서의 재작업률을 제로에 가깝게 줄였습니다. 불필요한 질의와 수정 작업을 최소화해 전체 개발 일정을 약 20% 단축시켰고, 결과적으로 경진대회 동상을 수상했습니다. 포스타입에서도 주도적인 자세(Take Ownership)로 투명하게 지식을 공유하며 최고의 'One Team' 시너지를 창출하겠습니다.
