# 🏢 알디에스(주) 자기소개서 (IT 운영 개발 신입사원)

## 1. 조직 적합성

[신뢰를 잇는 디지털 혁신의 든든한 백본]
알디에스는 오뚜기 그룹의 전산 인프라를 무결점으로 방어하는 동시에, 사내 생성형 AI 'ODIN(오딘)' 론칭과 업무 자동화(RPA) 확산을 통해 그룹 전체의 비즈니스 프로세스 혁신(DX)을 선도하는 핵심 엔진입니다. 저는 급변하는 IT 트렌드 속에서도 '시스템의 안정성'이라는 최우선 가치를 지켜내며, 신기술을 현업의 실질적인 효율성으로 치환해 내는 알디에스의 흔들림 없는 철학에 깊이 공감하여 IT 운영 개발 직무에 지원하였습니다.

시스템의 안정성은 철저한 데이터베이스 정규화와 트래픽 격리 구조에서 출발한다고 믿습니다. 저는 '하이브리드 AI 주식 리밸런싱 앱' 프로젝트에서 백엔드 아키텍처와 AI 파이프라인 연동을 총괄하며, 신기술 도입이 기존 시스템의 병목이 되지 않도록 설계하는 역량을 길렀습니다. 초기 시스템은 단일 테이블 위주의 비정규화된 DB 구조와 동기식 AI 호출로 인해, 무거운 추론 연산 시 톰캣의 메인 스레드가 고갈되어 전체 서버가 마비될 위험이 있었습니다. 

이를 해결하기 위해 데이터베이스를 3정규형(3NF)으로 재설계하여 무결성을 확보하고, Spring의 WebClient와 @Async를 활용해 AI 비동기 전용 스레드 풀을 격리하는 아키텍처를 도입했습니다. 그 결과, 대규모 AI 추천 동시 요청 상황에서도 백엔드 코어 API의 스레드 차단 시간을 0ms로 유지하며 논블로킹 파이프라인의 완벽한 안정성을 입증했습니다. 나아가 특허 출원과 경진대회 동상이라는 성과도 거둘 수 있었습니다.

오뚜기 그룹의 전산 인프라는 생산, 물류, 영업 등 전사적 밸류체인의 연속성을 보장해야 하므로 '무결점 운영'이 생명입니다. 저는 이러한 시스템 최적화 경험을 바탕으로, 알디에스가 추진하는 스마트팩토리 및 차세대 ERP 환경에서 발생할 수 있는 병목을 선제적으로 차단하겠습니다. 혁신적인 IT 기술을 오뚜기의 안정적인 인프라 위에 견고하게 이식하여, 그룹의 지속 가능한 성장을 뒷받침하는 듬직한 신입사원이 되겠습니다.

## 2. 직무 적합성

[원장 불일치 제로를 달성한 무결점 트랜잭션 제어 역량]
알디에스의 IT 운영 개발 직무는 다수 계열사의 방대한 ERP 데이터와 트랜잭션을 병목이나 유실 없이 정확하게 처리하는 것이 핵심입니다. 저는 '주식 매수/매도 이상거래 감지 시스템' 개발 프로젝트에서 트레이딩 API 및 리스크 관리 파트를 전담하며, 분산 환경에서의 데이터 정합성 보장과 대용량 배치 처리 역량을 체득했습니다.

당시 시스템은 주문 접수부터 원장 기록, 정산까지 복잡한 단계가 연결되어 있어, 대규모 트래픽 발생 시 이벤트가 유실되거나 동시성 이슈로 인해 자금 데이터의 불일치가 발생할 위험이 컸습니다. 저는 이를 해결하고자 메시징 큐와 분산 락을 결합한 다중 안전망 아키텍처를 설계했습니다. 먼저, 클라이언트의 주문 요청을 Kafka 비동기 토픽으로 발행해 API 지연을 최소화하는 동시에, Redis 기반의 1차 락과 DB의 Unique 제약 조건을 통한 2차 방어망을 구축하여 네트워크 재전송 시에도 멱등성을 보장했습니다.

또한, 다중 인스턴스 환경에서 동일 유저의 체결 이벤트가 동시에 처리되며 발생하는 경쟁 조건(Race Condition)을 방지하기 위해 분산 락 알고리즘을 적용했습니다. 나아가, 75,000건 이상의 대용량 배치 처리 중 상태 변화로 인해 오프셋이 밀리며 일부 레코드가 누락되는 치명적인 버그를 발견했습니다. 이를 즉각적으로 커서(Cursor) 기반 페이지네이션으로 전면 교체함으로써 데이터 누락 문제를 근본적으로 차단했습니다.

그 결과, 75,000건의 원장 엔트리와 대규모 정산 결과를 단 한 건의 누락도 없이 처리하였고, 최종 대사 프로세스에서 데이터 간 불일치(Recon Diff) '0건'을 검증해 내며 시스템의 완벽한 무결성을 입증했습니다. 알디에스 입사 후에도 이러한 트러블슈팅 경험과 정교한 트랜잭션 제어 능력을 십분 발휘하겠습니다. 오뚜기 그룹의 핵심 ERP 및 포털 시스템 운영 시 발생할 수 있는 데이터 정합성 이슈를 사전에 차단하고, 무중단 IT 서비스를 제공하는 데 기여하겠습니다.

## 3. 의사소통 방식 및 협업

[단일 진실 공급원(SSOT) 구축을 통한 선제적 갈등 예방]
개발 조직에서 진정한 소통이란, 단순히 갈등이 발생했을 때 이를 원만히 무마하는 것이 아니라 갈등이 발생할 수밖에 없는 구조적 원인을 사전에 제거하는 시스템을 만드는 것이라고 생각합니다. 알디에스와 같이 다양한 현업 부서 및 그룹 계열사와 밀접하게 연계되어 IT 서비스를 운영하는 환경에서는, 요구사항의 오해나 인터페이스 불일치를 예방하는 '선제적 소통'이 필수적입니다.

과거 팀 프로젝트 당시, 백엔드와 프론트엔드 간의 API 명세나 데이터베이스 설계가 명확하게 합의되지 않은 상태에서 코딩을 시작하여 큰 어려움을 겪은 경험이 있습니다. 개발 도중 서로의 구현 방식에 대해 수시로 질문하며 병목이 발생했고, 결국 인터페이스 불일치로 인해 이미 작성한 코드를 대폭 수정해야 하는 소모적인 갈등과 일정 지연을 초래했습니다. 저는 이 문제의 핵심이 팀원 개인의 소통 능력이 아니라, 서로가 신뢰할 수 있는 '합의된 사전 구조의 부재'에 있다고 판단했습니다.

이를 교훈 삼아 후속 'AI 주식 리밸런싱 앱' 프로젝트에서는 코드를 단 한 줄도 작성하기 전에 선제적인 소통 프로세스를 도입했습니다. 기획 단계에서 프론트엔드, AI 파트 담당자들과 주도적으로 회의를 열어 각 API의 Request/Response 스펙, 에러 코드 규격, DB 테이블 관계를 철저하게 사전 정의했습니다. 이렇게 합의된 내용을 Notion 기반의 API 명세서로 문서화하여, 모든 팀원이 이를 '단일 진실 공급원(SSOT)'으로 삼도록 규칙을 세웠습니다. 개발 중 의문점이 생기면 서로 구두로 묻기 전에 문서를 먼저 확인하고, 변경 사항은 즉각 문서에 동기화하는 문화를 정착시켰습니다.

결과적으로 인터페이스 불일치로 인한 재작업과 불필요한 감정 소모를 제로에 가깝게 줄일 수 있었고, 4인으로 구성된 크로스 도메인 팀이 유기적으로 맞물려 전체 개발 일정을 성공적으로 단축했습니다. 알디에스 입사 후에도 현업 부서의 요구사항을 명확한 기술 문서와 프로세스로 번역하여, 오해 없이 시스템이 원활하게 운영되도록 이끄는 소통의 브릿지 역할을 수행하겠습니다.
