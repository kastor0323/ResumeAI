# (주)이트리즈시스템 - JAVA 기반 웹 개발자 자기소개서

## 문항 1. 조직 적합성

### [고객사의 비전을 실현하는 기술 동반자]

개발자의 진짜 가치는 기술 그 자체에 머무는 것이 아니라 비즈니스 현장의 고충을 해결하고 고객이 신뢰할 수 있는 안정적인 시스템을 완성하는 데 있다고 믿습니다. 이트리즈시스템은 지난 17년 동안 금융, 공공, 제조, 유통 등 다양한 산업 분야에서 삼성카드, 현대카드, 우리은행, KT와 같은 대형 고객사들의 핵심 시스템 구축과 아웃소싱을 성공적으로 수행하며 시장의 깊은 신뢰를 쌓아왔습니다. 특히 자체 보안 솔루션인 DirectOTP 개발을 통해 핀테크 인증 시장에서도 독보적인 기술력을 증명하고 있는 점은 지속 가능한 기술 전문성을 지향하는 저의 개발 가치관과 완벽히 부합하여 지원하게 되었습니다.

다양한 산업군의 프로젝트를 수행하는 SI와 SM 환경에서는 새로운 도메인 지식을 신속하게 흡수하고 기술적 변화에 유연하게 대처하는 능력이 필수적입니다. 저는 컴퓨터공학을 전공하며 습득한 전산 기초 지식과 새로운 기술 스택을 빠르게 학습하여 즉시 실무에 적용하는 열정을 갖추고 있습니다. 이트리즈시스템이 금융권 차세대 시스템이나 대형 유통망 인프라 고도화 프로젝트를 전개할 때, 고객사의 비즈니스 로직과 시스템 요구사항을 정확하게 분석하고 데이터 무결성을 보장하는 안전한 코드를 설계하는 데 기여하겠습니다.

입사 후에는 이트리즈시스템의 전문성, 창의성, 열정이라는 핵심 가치를 늘 마음속에 새기며 일하는 방식에 완벽하게 녹아들겠습니다. 선배 개발자분들의 노하우를 스펀지처럼 빠르게 전수받고 다양한 프로젝트 현장 도메인 지식을 적극적으로 축적하여, 어떠한 돌발 상황이나 낯선 환경에서도 흔들리지 않는 대처 능력을 기르겠습니다. 이를 통해 파견지 고객사들로부터 이트리즈시스템의 엔지니어는 기술력과 책임감 면에서 가장 믿고 맡길 수 있다는 신뢰의 평가를 매 순간 받아내겠습니다. 신속하게 실무 1인분 분량을 완수하여 고객사의 정보화 혁신을 든든히 뒷받침하고 나아가 회사의 매출 성장과 대외적 가치를 함께 키우는 준비된 핵심 개발자가 되겠습니다.

## 문항 2. 직무 적합성

### [데이터 무결성을 사수하는 견고한 백엔드 역량]

안정성이 생명인 금융권 차세대 시스템이나 대형 유통망 인프라를 다루는 SI 프로젝트에서는 완벽한 데이터 정합성을 확보하는 기술력이 최우선입니다. 저는 주식 매수와 매도 이상거래 감지 시스템을 개발할 당시 Trading API 및 리스크 관리 모듈 개발을 전담하며 분산 시스템 아키텍처와 동시성 제어 역량을 키웠습니다. 당시 대량의 거래 이벤트가 동시에 집중될 때 데이터 유실과 정합성 불일치를 원천 차단하고 원장을 안전하게 검증하는 과제를 해결해야 했습니다.

이를 위해 주문 데이터의 멱등성 보장 처리를 다중 안전망으로 구축했습니다. 먼저 유저 고유 식별자와 주문 식별자 복합키를 활용해 Redis에서 1차 락을 수행하여 중복 요청을 방지했습니다. 또한 데이터베이스 고유 제약 조건을 2차 백업 안전망으로 두어 네트워크 불안정으로 인한 재전송 환경에서도 비즈니스 결과의 유일성을 철저하게 보장했습니다. 다중 리스크 인스턴스 환경에서 동일 유저의 체결 이벤트가 동시에 발생하여 생기는 경쟁 조건을 해결하기 위해 Redis 분산 락을 설계하고 5초의 타임아웃 설정을 적용하여 데이터의 실시간 일관성을 완벽히 사수했습니다.

이 과정에서 75,000건 이상의 대용량 배치 처리 중 상태 변화로 인해 오프셋이 밀려 데이터가 누락되는 버그를 발견했습니다. 이를 해결하고자 기존 오프셋 기반 페이지네이션을 최종 처리된 식별자를 비교해 조회하는 커서 기반 페이지네이션 방식으로 전면 교체하여 누락율 0%를 달성했습니다. 그 결과 거래 내역과 잔고 테이블 간 정합성을 교차 검증하는 대사 프로세스에서 오차 0건의 무결점을 증명했습니다. 이와 같이 다져진 Java 기반 웹 서비스 구현 능력과 데이터베이스 최적화 기술은 이트리즈시스템이 수주하는 다양한 대규모 시스템 통합 현장에서 즉시 1인분의 몫을 수행하며 무결점 개발을 완수하는 든든한 밑거름이 될 것입니다.

## 문항 3. 의사소통 방식 및 협업

### [사전 예방의 소통 구조로 마찰 없는 협업을 이끌다]

진정한 협업 효율성은 개발 도중 발생할 수 있는 소통 마찰과 병목을 선제적으로 예방할 수 있는 시스템 구축 여부에 달려있다고 믿습니다. 이전 팀 프로젝트 당시 백엔드와 프론트엔드 간의 명확한 API 합의가 없는 상태로 개발을 진행했다가, 서로 다른 이해로 인해 인터페이스가 불일치하여 코드를 다시 작성해야 하는 잦은 재작업과 소통 지연의 갈등을 경험했습니다. 

저는 이러한 마찰이 팀원 간의 개인적 불화가 아니라 협의된 사전 약속과 시스템의 부재에서 비롯된 구조적 문제라고 판단했습니다. 이를 해결하고자 다음 하이브리드 AI 주식 리밸런싱 앱 개발 프로젝트에서는 본격적인 코딩에 들어가기에 앞서, 설계 단계에서 팀원들을 적극적으로 설득하여 공동 회의를 소집했습니다. 이 회의를 통해 데이터베이스 스키마 설계부터 시작하여 각 기능별 Request 및 Response 스펙, 상세 에러 코드 규격을 철저하게 사전 정의했습니다. 정의된 내용을 모든 팀원이 실시간으로 동일하게 신뢰하고 공유할 수 있도록 공동 문서화하여 단일 진실 공급원으로 활용했습니다.

또한 코드 병합 시 발생할 수 있는 오류를 예방하기 위해, 프론트엔드와 백엔드가 서로의 연관 영역에 대한 상호 정합성을 교차 검토하는 풀 리퀘스트 기반의 동료 검토 제도를 제안하여 도입했습니다. 이처럼 시스템화된 사전 예방 소통 방식을 적용한 결과, 개발 단계에서의 불필요한 질의 시간과 오류 수정으로 인한 재작업률을 제로에 가깝게 대폭 줄였으며, 결과적으로 전체 프로젝트 일정을 약 20% 단축하고 교내 기업연계 프로젝트 경진대회 동상 수상이라는 결실을 거두었습니다. 프로젝트가 끝난 후 팀원들로부터 소통 병목 없이 각자 영역에 완벽하게 몰입할 수 있어 최고의 협업 경험이었다는 피드백을 받았습니다. 입사 후에도 다양한 협력 부서 및 고객사 엔지니어들과 일할 때 이처럼 합리적인 소통 체계를 주도해 나가겠습니다.
