# Specs 컨디션 체크 워크플로우

## 📋 개요

이 명령어는 `1_my_specs/specs/` 폴더 내의 모든 마크다운 파일과 `README.md` 매핑 테이블을 싹 다 긁어모아 데이터 통계(I/O)를 내고, 분석 지능을 담당하는 **[@스펙관리마스터] 스킬**에게 통째로 넘겨 평가표를 받아내는 **리포팅 자동화 파이프라인**입니다.

---

## 🔄 워크플로우 실행 단계

> ⚠️ **주의:** 이 워크플로우는 "충분하다/부족하다" 등의 가치 판단을 직접 내리지 않습니다. 데이터 취합과 파일 저장만 담당하며 평가는 `스펙관리마스터`가 합니다.

### 1️⃣ 전체 DB 긁어오기 (Batch Read)
* `1_my_specs/specs/` 내 하위 폴더(`base`, `experiences`, `competencies`, `traits`, `motivations`)들에 있는 모든 `.md` 파일의 목록과 프론트매터 데이터를 메모리에 로드합니다.
* `1_my_specs/specs/README.md` 스펙 매핑 테이블 데이터도 함께 로드합니다.

### 2️⃣ 마스터 호출 (Call Brain)
* 취합한 엄청난 양의 메타데이터 배열을 매개변수로 삼아 **"`.agent/skills/스펙관리마스터.md` 스킬의 [모드 2]를 실행해"** 라고 시스템에 명령합니다.
* 워크플로우는 마스터 연산이 끝날 때까지 얌전히 대기(Hold)합니다.

### 3️⃣ 리포트 수신 및 저장 (Report Export)
* 마스터가 1) 구조 검증, 2) 정량적 성과 현황, 3) 커버리지, 4) 스펙 코칭 피드백이 담긴 **최종 보고서 마크다운 블록**을 뱉어내면 이를 수신합니다.
* 수신한 블록을 `2_target_companies/reports/specs_report_YYYY-MM-DD.md` (오늘 날짜) 파일로 생성하여 저장(`write_to_file`)합니다.

### 4️⃣ 종료 브리핑 (Finish)
* "스펙 점검 리포트가 성공적으로 발행되었습니다. `reports/specs_report_...` 파일을 확인하시어 마스터의 코칭 피드백대로 스펙을 보강하세요!" 라는 메시지를 터미널 화면에 출력하고 워크플로우를 종료합니다.
